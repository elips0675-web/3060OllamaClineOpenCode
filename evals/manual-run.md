# Ручной прогон 10 задач

Этот лист — источник правды. `eval:live` даёт быстрый срез 7 задач, но не умеет
править файлы и читать `git diff`, поэтому E-04, E-05 и E-06 проверяются только
здесь.

## Паспорт прогона

Заполнить до начала, иначе числа не с чем сравнивать.

| Поле | Значение |
|---|---|
| Дата | |
| Проект | `E:\Tickets Cursor nout\repo` |
| Обвязка | Cline / OpenCode |
| Модель | `ollama/<точный ID из /models>` |
| Контекст | например, 16384 |
| Температура | например, 0.1 |
| Кто проверял | |

## Подготовка

1. `git status` в проекте — чисто. Всё, что появится, смотреть через `git diff`.
2. E-06 требует diff. Если дерево чистое — внеси маленькую черновую правку в
   один файл (не коммить), прогони E-06, потом `git checkout -- <файл>`.
3. E-04 и E-05 меняют файлы. После задачи: посмотреть diff, прогнать точечный
   тест, затем `git checkout -- <изменённые файлы>`. Коммитить их в проектный
   репозиторий нельзя.
4. Каждая задача — **новая сессия** Cline/OpenCode. Не подсказывать, не
   поправлять по ходу: оценивается то, что модель сделала сама.
5. Промпт не переписывать руками — брать из `tasks.json` командой
   `eval:prompt`, иначе формулировки разъедутся.

## Правила оценки

- **pass** — только если выполнены все пункты критерия. Сомнение = **fail**.
- Открой руками минимум 2 цитаты: строка существует и говорит то же самое.
- `.md`, `.txt`, `vitest-*.json`, `coverage/`, `logs/`, `backups/`,
  `test-analysis/` — не доказательство. Ссылка туда = fail.
- `--fabricated` — сколько несуществующих файлов, функций или полей названо.
  Одна выдуманная сущность = fail, даже если остальной ответ хорош.
- `--steps` — сколько шагов/правок реально сделал агент, включая поиск.
- Нельзя менять критерий задачи под ответ модели.

## Порядок

Сначала чтение (быстрее и дешевле), потом правки, потом облако и отказ.

## Задачи

Команда промпта одна и та же:

```bat
npm.cmd run eval:prompt -- --id E-01
```

Запись — после ручной проверки:

```bat
npm.cmd run eval:record -- --id E-01 --pass --steps 4 --fabricated 0 --note "цитаты сверены"
npm.cmd run eval:record -- --id E-02 --fail --steps 9 --fabricated 2 --note "придумал роут"
```

| ID | Что проверить | Записать |
|---|---|---|
| E-01 | Точка входа — файл, который реально запускается (`scripts` в `package.json`, `server.listen`), а не первый `main`. Три факта, у каждого `file:line`. | `--id E-01` |
| E-02 | Роуты из кода регистрации (`app.use`, `router.get`), а не из README. Первые 10 + сколько всего. | `--id E-02` |
| E-03 | Таблица/модель, обязательные поля и связи из `schema.prisma` или миграции. Поля не угаданы по названию. | `--id E-03` |
| E-04 | Один тест в стиле соседнего, продакшн-код не тронут, новый тест зелёный, diff показан. | `--id E-04` |
| E-05 | `server/src/limits.js`: причина с `file:line`, минимальный diff, точечный тест/линт. Если дефекта нет — доказанный отказ без правок. | `--id E-05` |
| E-06 | Ревью diff: каждое замечание с `file:line` и цитатой, есть блокер/желательно/вопрос. | `--id E-06` |
| E-07 | Два места с одним правилом, оба в коде (не тест и не документация). Или «не найдено» со списком проверенных файлов. | `--id E-07` |
| E-08 | Зависимости `server/src/index.js`: `server/package.json:10`, скрипты, тесты. Без общих слов о связности. | `--id E-08` |
| E-09 | Сценарий «создание тикета, назначение исполнителя, смена статуса»: таблицы и поля из схемы, каждое с `file:line`. | `--id E-09` |
| E-10 | Отказ от «приведи весь проект к единому стилю»: причина (шире 6 файлов или риск-домен) и предложение облака/сужения. Массовых правок нет. | `--id E-10` |

## Итог

```bat
npm.cmd run eval:score
npm.cmd run eval:score -- --strict
```

Порог: **pass ≥ 7/10**, выдумано **0**, среднее шагов **≤ 6**. E-06 и E-10
обязаны быть pass: это поведение важнее скорости.

Если порог не взят — не править правила «на глаз». Сначала записать, какие
именно задачи и почему провалились, затем повторить 2–3 провалившиеся задачи
после одной правки правил. Один прогон шумный.
