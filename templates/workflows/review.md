# /review — ревью diff по фактам

## Когда

Есть готовый diff или PR, нужно найти риски, а не пересказать изменения.

## Шаги

1. Получи diff (git MCP или `git diff`); не читай весь репозиторий.
2. Для каждого изменённого файла прочитай контекст вокруг правки.
3. Проверь по пунктам: логика, границы, ошибки, безопасность, данные, тесты.
4. Каждое замечание — с `file:line` и цитатой; без цитаты — не замечание.
5. Раздели: «блокер», «желательно», «вопрос».
6. Отчёт: вердикт, список замечаний, что не проверено.

## Стоп

- Diff больше 10 файлов → ревью по частям или облако.
- Затронуты деньги/доступы/миграции → облако.

## Запреты

- Не пересказывать diff.
- Не предлагать «переписать всё».
- Не выдавать стилистику за блокер.
