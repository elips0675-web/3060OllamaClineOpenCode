# /eval — измерить агента, а не поверить в него

## Когда

После правки правил, промптов или смены модели. Задача — получить число, а не
впечатление «вроде стало лучше».

## Шаги

1. Автоматический срез (7 из 10 задач, read-only):
   `npm.cmd run eval:live -- --root <проект> --out evals/live-<дата>.json`
2. Прочитать таблицу: `pass`, шаги, выдуманные файлы, причину fail.
3. Ручной прогон оставшихся задач в Cline: `npm.cmd run eval:prompt -- --id E-04`.
4. Записать каждый результат: `npm.cmd run eval:record -- --id E-04 --pass|--fail
   --steps N --fabricated N --note "…"`.
5. Порог: `npm.cmd run eval:score -- --strict` — pass ≥ 7/10, выдумано 0,
   среднее шагов ≤ 6.

## Правило разбора

Провал сначала объясняется дефектом правил/инструмента (нет цитаты — нечем
проверить; нет доступа — не тот инструмент) и только потом слабостью модели.
Веса и «обучение» не трогаются, пока не исправлены правила.

## Запреты

- Не записывать pass без проверки цитаты руками.
- Не менять `evals/tasks.json` под результат прогона: задача — измеритель.
- Не сравнивать прогоны разных версий задач.
