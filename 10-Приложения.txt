1. MODELEFILE: ОТКУДА БЕРЁТСЯ 10.1 ГБ ИЗ 12

  Файл: models\Modelfile-14b-q4 (он же в комплекте, папка models\)

      # Профиль A: RTX 3060 12 ГБ VRAM (стандартная карта)
      # Модель целиком в VRAM: 9.0 ГБ веса + ~1.1 ГБ KV-кэш (q8) = ~10.1 ГБ из 12.
      # Ожидаемая скорость: 25-35 ток/с генерация, 200-400 ток/с prefill.

      FROM qwen2.5-coder:14b

      PARAMETER num_ctx 12288
      PARAMETER num_gpu 99
      PARAMETER temperature 0.2
      PARAMETER top_p 0.9

  Три строки, которые нельзя терять:
    FROM               базовый тег из ollama pull; если тега нет, pull упадёт
    num_ctx 12288      без этой строки Ollama возьмёт дефолт 4096 и начнёт
                       резать файлы — самая частая «загадка» локальных моделей
    num_gpu 99         просит уложить все слои в GPU; при нехватке VRAM
                       Ollama сама сделает split и покажет его в ollama ps

  Остальные четыре профиля отличаются только этими значениями:
    Modelfile-14b-q6    FROM qwen2.5-coder:14b-instruct-q6_K, num_ctx 16384
                        (профиль B: только для 16 ГБ VRAM)
    Modelfile-7b-q8     FROM qwen2.5-coder:7b-instruct-q8_0,  num_ctx 16384
    Modelfile-7b-q5     FROM qwen2.5-coder:7b-instruct-q5_K_M, num_ctx 16384
                        (профиль E: 5.4 ГБ веса, ~6.5 ГБ с KV — запас VRAM)
    Modelfile-tiny      FROM qwen2.5-coder:1.5b,             num_ctx 4096

  Обратите внимание: у 14B q4 контекст 12288 намеренно меньше, чем у q6 и 7B.
  На 3060 12 ГБ каждый лишний килобайт контекста — это KV-кэш в той же VRAM,
  а для карточки в 5 КБ и правки одного файла 12288 хватает с запасом.

  Проверка после установки (обязательна):
      ollama show swiftmatch-coder-14b --modelfile | findstr num_ctx
      ожидается: PARAMETER num_ctx 12288
      ollama ps      ->  колонка PROCESSOR = 100% GPU


2. .CLINERULES: ЧЕМ ВКЛЮЧАЕТСЯ ФРАЗА «ДОДЕЛАЙ ИЗ ЧТО ДОДЕЛАТЬ»

  Файл: .clinerules в корне проекта (в git не добавлен: .git/info/exclude).
  Полный текст — 11 разделов; ниже те два, без которых фраза не работает.

  ## 10. Триггер «Доделай из Что доделать»

  Если человек пишет «Доделай из Что доделать», «следующая задача»,
  «что дальше»:
  1. НЕ читай «Что доделать.txt» целиком: ~18 тыс. токенов не влезают
     в контекст 12288.
  2. Выполни в терминале: node scripts/next-task.mjs --local --out tmp/next-task.txt
     (если назван ID — --id <ID>).
  3. Прочитай только tmp/next-task.txt.
  4. Работай строго по разделу «ПРОМПТ ДЛЯ АГЕНТА»; файл — из раздела
     «СРЕЗ ДЛЯ ОДНОГО ПОДХОДА», другие файлы не трогай.
  5. Exit 1 от скрипта значит «брать нечего»: покажи
     node scripts/next-task.mjs --list.
  6. Текст задачи берётся из карточки, из памяти модели — нельзя.

  ## 11. Локально или в облако

  Локальная модель (14B на 3060): одна правка в одном файле, объяснение файла,
  мелкий рефакторинг. Облако: больше одного файла, SQL/схема, разбор красных
  гейтов, ревью диффа, тесты на 200+ строк.
  Локальная ошиблась дважды — скажи «нужна эскалация в облако» и остановись.

  ## 11.1 Кто делает коммит

  Пункт 7 описывает порядок чекпойнта, но исполнитель — не локальная модель.
  Локальный агент НЕ выполняет git add / git commit / git push: он показывает
  дифф, вывод гейтов и точный список файлов, коммит делает человек. Причина:
  14B не прогоняет полный набор гейтов надёжно, а ошибка в составе файлов
  уходит в main без ревью. Облачный агент коммитит только по прямому указанию
  человека в текущей сессии.

  Остальные разделы (1-9) коротко: работать только из бэклога; npm.cmd /
  npx.cmd; зелёный минимум перед словом «готово»; зеркала test/ только
  скриптом; запреты по коду и any; запрещённые команды без разрешения
  (npm ci, git reset --hard, git checkout -- <файл>, prune, правка .env);
  чекпойнт после каждого логического блока; порядок работы; «не уверен —
  спроси».

  Проверка, что триггер живой:
      findstr /i "Доделай из Что доделать" .clinerules      (из корня проекта)


3. OPENCODE.JSON: МЕРЖИТЬ, А НЕ ЗАМЕНЯТЬ

  Сейчас файл opencode.json в проекте содержит ровно это:

      {
        "$schema": "https://opencode.ai/config.json",
        "instructions": [".opencode/persona.md", "AGENTS.md"]
      }

  Строка instructions — не декорация: без неё агент теряет правила проекта
  (persona + AGENTS.md). Если заменить файл целиком на пример из 08, правила
  пропадут, и агент начнёт «улучшать» проект по своему усмотрению.

  Правильный результат после установки моделей Ollama (добавлены model,
  default_agent, providers и agents; instructions на месте):

      {
        "$schema": "https://opencode.ai/config.json",
        "instructions": [".opencode/persona.md", "AGENTS.md"],
        "model": "ollama/swiftmatch-coder-14b:latest",
        "default_agent": "local",
        "providers": {
          "ollama": {
            "models": {
              "swiftmatch-coder-14b:latest": {
                "name": "swiftmatch-coder 14B q4 · ctx 12k",
                "limit": { "context": 12288, "output": 4096 },
                "capabilities": {
                  "tools": true,
                  "input": ["text"],
                  "output": ["text"]
                }
              },
              "swiftmatch-coder-7b-q5:latest": {
                "name": "swiftmatch-coder 7B q5_K_M · ctx 16k",
                "limit": { "context": 16384, "output": 4096 },
                "capabilities": {
                  "tools": true,
                  "input": ["text"],
                  "output": ["text"]
                }
              },
              "gpt-oss:120b-cloud": {
                "name": "gpt-oss:120b-cloud · Ollama Cloud",
                "limit": { "context": 131072, "output": 16384 },
                "capabilities": {
                  "tools": true,
                  "input": ["text"],
                  "output": ["text"]
                }
              }
            }
          }
        },
        "agents": {
          "local": {
            "description": "Основная работа на 3060: один файл, узкая правка",
            "mode": "primary",
            "steps": 10,
            "permissions": [
              { "action": "webfetch", "resource": "*", "effect": "deny" },
              { "action": "websearch", "resource": "*", "effect": "deny" }
            ]
          },
          "cloud": {
            "description": "Эскалация: многофайловые задачи, ревью, миграции",
            "mode": "primary",
            "model": "opencode/deepseek-v4.1-flash-free"
          }
        }
      }

  Порядок: сначала в /models посмотреть точный ID модели, вписать его вместо
  примера, затем проверить, что OpenCode стартует. ID не угадывать: при
  неверном имени OpenCode либо не стартует, либо молча подставляет другую
  модель. Второй способ — не писать руками, а выполнить
  "…\switch-ai.bat" local|cloud: скрипт смержит эти ключи с текущим файлом
  (instructions сохранит) и оставит бэкап opencode.json.bak-<дата>.

  Ключи — OpenCode V2: providers, agents, permissions (множественное число).
  Старые provider / agent / permission V2 ещё читает, но они помечены
  устаревшими. Форматы внутри одного агента не смешивать.

  Откат: сохранить копию opencode.json перед правкой (opencode.json.bak) —
  это два ключа, восстановить вручную дело одной минуты.


4. SCRIPTS/NEXT-TASK.MJS: КОНТРАКТ ВЫБОРА ЗАДАЧИ

  Файл: scripts/next-task.mjs (597 строк) + scripts/next-task.test.mjs
  (46 тестов). Источник правды — репозиторий проекта; в комплекте лежит
  снимок (30.10.2026) плюс package.json с командой test:next, так что
  поведение можно прогнать здесь же: npm.cmd run test:next.

  Контракт командной строки:
      node scripts/next-task.mjs                     по приоритетам бэклога
      node scripts/next-task.mjs --local             только то, что уходит на 3060
      node scripts/next-task.mjs --route             одна строка: local|cloud + причина
      node scripts/next-task.mjs --list              таблица всех пунктов
      node scripts/next-task.mjs --id QA-01          конкретный пункт
      node scripts/next-task.mjs --json              машинный вывод
      node scripts/next-task.mjs --out tmp\next-task.txt   карточку в файл
      node scripts/next-task.mjs --root <путь>       гейты из package.json проекта
      node scripts/next-task.mjs --queue-only        только «Очередь этапов»
      node scripts/next-task.mjs --include-blocked   разрешить blocked
      node scripts/next-task.mjs --allow-no-evidence разрешить без file:line

  Статусы пункта:
      ready       можно брать (для --local нужен ещё evidence = file:line
                  и маршрут local)
      blocked     ждёт внешнего действия (ключи, домен, staging)
      closed      выполнено — не выдаётся даже через --id
      decision    принятое решение, не задача — не выдаётся никогда
      no-evidence открыто, но без цитаты file:line — по умолчанию не выдаётся

  Что гарантирует скрипт:
    - детерминированность: тот же бэклог -> та же задача, решение не за моделью;
    - дедупликация по ID: один пункт не выбирается дважды под разными именами;
    - разрешение «голого» имени файла (chats.tsx -> src/pages/chats.tsx) только
      при единственном совпадении в репозитории, папка test/ исключена;
    - карточка содержит ID, строку бэклога, цитату file:line, ОДИН файл,
      гейты и готовый промпт для агента;
    - строка «Маршрут» в карточке (функция routeFor, экспортируется):
          нет цитаты file:line           -> облако: такой пункт не берут
          риск-домен (см. ниже)          -> облако (/next-cloud): <домен>
          один файл + file:line          -> 3060: один файл, один подход
          несколько файлов (N)           -> 3060 по одному файлу, подходов: N
                                            (+ подсказка про /next-cloud)
      Порядок именно такой: сначала правило проекта (цитата), потом риск,
      потом число файлов. Риск-домены ищутся по тексту пункта и по путям
      файлов (функция riskyDomain, экспортируется):
          money   Stripe, платёж, подписка, premium, оплата, возврат средств,
                  refund, выплата, комиссия, invoice, billing
          access  JWT, OAuth, auth, CSRF, adminAuth, секрет, токен, уязвимость,
                  IDOR, rate-limit, пароль, sanitiz, XSS, SQL-инъекция
          schema  миграция, mysql_schema, ALTER/CREATE TABLE, ENUM, CHECK,
                  schema, схема, индекс
          infra   docker, compose.yaml, deploy.yml, nginx, деплой, kubernetes
      Это ключевые слова, а не оценка сложности и не проверка кода. Скрипт
      не выбирает провайдера и не переключает модель: он только печатает
      решение, а запуск модели остаётся за человеком;

    - `--route` печатает ровно одно решение в формате `local<TAB>текст` или
      `cloud<TAB>текст`, карточку не печатает. В `--json` то же решение лежит
      в поле `route` ({ target, reason, text }), где reason — одно из
      no-citation / money / access / schema / infra / single-file / stepwise;
    - заблокированный бэклог (файл открыт в Excel/Word/редакторе, held другой
      программой) даёт понятное сообщение и код 2, а не стек Node.js и код 1:
          Файл бэклога заблокирован другой программой: <путь>
          Закройте его (Excel, Word, редактор, синхронизация) и повторить.

  Коды выхода:
      0  задача найдена, карточка напечатана
      1  брать нечего (все подходящие пункты закрыты/заблокированы)
      2  ошибка аргументов или чтения: нет файла бэклога, файл заблокирован

      node node_modules\vitest\vitest.mjs run scripts/next-task.test.mjs

5. ТРИ ВЕЩИ, О КОТОРЫХ ПРЕДУПРЕЖДАЕТ ПРАКТИКА

  5.1 Возраст локальной модели
      Qwen2.5-Coder — модель конца 2024 года; комплект датирован октябрём 2026.
      Она остаётся рабочей лошадкой для 12 ГБ, но перед покупкой/установкой
      стоит посмотреть, не появилось ли более свежее семейство coder в теге 14B:
          ollama list                     (что уже скачано)
          ollama.com/library              (что существует)
      Если появилось — берите её тем же способом: свой Modelfile, свой num_ctx.
      Менять надо только строку FROM, остальные параметры переносятся.

  5.2 Кириллица в пути
      Комплект лежит в D:\ИИ агент\3060 16 gb\. Ollama, VS Code и Node это
      переваривают, но отдельные нативные модули и старые утилиты — нет.
      Если что-то не запускается и в логе есть «не найден путь» или кракозябры
      в пути — перенесите папку в латиницу: D:\ai-agent\3060-16gb\
      и поправьте "path" в swiftmatch-3060.code-workspace и docs.url в
      конфиге Continue.

  5.3 Контекст Cline 12288 — на грани
      Cline — агент: системный промпт и описания инструментов съедают
      3-4 тыс. токенов, на файл остаётся ~8 тыс. Если Cline начинает терять
      начало диалога или обрезает файл — это контекст, а не «модель поглупела».
      Варианты по порядку: вести задачу в OpenCode (аккуратнее с контекстом),
      поднять context до 16384 и сразу проверить ollama ps на CPU/GPU split.
      На 12 ГБ 16384 — это уже с риском split: KV-кэш растёт вместе с ctx.
