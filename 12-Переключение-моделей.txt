ПЕРЕКЛЮЧЕНИЕ МОДЕЛЕЙ: ЛОКАЛЬНО ↔ ОБЛАКО ОДНОЙ КОМАНДОЙ (Cline + OpenCode)
Комплект 3060 12 ГБ VRAM / 16 ГБ ОЗУ. Дата: 30.10.2026
================================================================================

Зачем этот файл: 05 объясняет, зачем вообще облако, 08 — где вводить команды,
09 — что держать под рукой. Здесь — как переключить модель сразу в двух
инструментах (Cline в VS Code и OpenCode в терминале), не правя настройки руками.

Скрипт НЕ автоматический: он не решает, когда эскалировать. Решение принимает
человек (правило эскалации), а скрипт выполняет его одной командой. Автоперехода
«локальная ошиблась -> само ушло в облако» нет и не будет: см. «Что доделать»,
раздел 3 «НЕ ДЕЛАТЬ».

1. КОРОТКО
--------------------------------------------------------------------------------

    cd /d D:\swiftmatch1bdnoutprodpart1
    "D:\ИИ агент\3060 16 gb\switch-ai.bat" status
    "D:\ИИ агент\3060 16 gb\switch-ai.bat" local
    "D:\ИИ агент\3060 16 gb\switch-ai.bat" cloud

Путь к комплекту подставьте свой: скрипт лежит в корне комплекта рядом с
00-12, а работает с ТЕКУЩИМ каталогом (корнем проекта). Поэтому запускать его
надо из корня проекта, а не двойным щелчком из папки комплекта — иначе он
честно откажется: «Это корень комплекта, а не проект».

Порядок для Cline:

    1) закрыть VS Code;
    2) switch-ai.bat local-q5   (или другой профиль);
    3) открыть VS Code — Cline читает состояние при старте.

Порядок для OpenCode:

    1) switch-ai.bat local       (конфиг читается при старте OpenCode);
    2) в уже открытой сессии модель не меняется: /models или новая сессия;
       если не помогло — перезапустите opencode.

Если VS Code закрывать не хочется, переключите только OpenCode:

    "D:\ИИ агент\3060 16 gb\switch-ai.bat" local --opencode-only

3. ОТКУДА БЕРУТСЯ МОДЕЛИ
--------------------------------------------------------------------------------

02-Установить-локально.bat создаёт сборки под именами комплекта:

    [1] qwen2.5-coder:14b                -> swiftmatch-coder-14b
    [2] qwen2.5-coder:14b-instruct-q6_K  -> swiftmatch-coder-14b-hq
    [3] qwen2.5-coder:7b-instruct-q8_0   -> swiftmatch-coder-7b
    [4] qwen2.5-coder:1.5b               -> swiftmatch-coder-tiny
    [5] qwen2.5-coder:7b-instruct-q5_K_M -> swiftmatch-coder-7b-q5

Проверка, что нужная сборка есть:

    ollama list
    ollama show swiftmatch-coder-7b-q5 --modelfile | findstr /i "num_ctx"
    ollama ps

В ollama ps колонка PROCESSOR должна быть 100% GPU. Если появился CPU/GPU
split — срезайте num_ctx или берите квант легче (см. 00, «Ваша конфигурация»).

Точный ID для OpenCode — это ollama/<имя>:latest; скрипт сам сверяет имя с
живым /api/tags и подставляет существующий тег. Придумывать ID не нужно.

4. Q4_K_M, Q5_K_M ИЛИ Q8_0
--------------------------------------------------------------------------------

  Квант     Вес 7B    Вес 14B   Итог на 3060            Когда
  --------  --------   --------  ----------------------  ---------------------
  q4_K_M    4.7 ГБ     ~9.0 ГБ   14B: ~10.1 ГБ (ctx 12k) основной профиль local
  q5_K_M    5.4 ГБ     ~10.5 ГБ  7B: ~6.5 ГБ (ctx 16k)  local-q5
                                14B: не влезает в 12 ГБ
  q8_0      7.6 ГБ     ~15 ГБ    7B: ~8.1 ГБ (ctx 16k)  local7, если 14B не нужна

  Правило: для агента контекст важнее последних 1-2 % качества. Нужен запас
  VRAM и 16k контекста — берите 7B q5_K_M. 7B q8 качественнее, но съедает
  на 2 ГБ больше. 14B q5_K_M на 12 ГБ не рассматриваем: веса плюс KV-кэш
  выходят за границу и Ollama уедет на CPU.

  Собрать q5-модель вручную (то же, что пункт [5]):

    ollama pull qwen2.5-coder:7b-instruct-q5_K_M
    ollama create swiftmatch-coder-7b-q5 -f models\Modelfile-7b-q5
    ollama run swiftmatch-coder-7b-q5 "Сколько будет 2+2?"

  Факт с машины 3060 (30.10.2026): 7B q5_K_M при ctx 16384 — 6.5 ГБ VRAM,
  100% GPU, скорость примерно на 10 % ниже q4 при том же размере модели.

--------------------------------------------------------------------------------

Из cmd в корне проекта (путь к комплекту — свой):

    "D:\ИИ агент\3060 16 gb\switch-ai.bat" status
    "D:\ИИ агент\3060 16 gb\switch-ai.bat" local
    "D:\ИИ агент\3060 16 gb\switch-ai.bat" local7
    "D:\ИИ агент\3060 16 gb\switch-ai.bat" local-q5
    "D:\ИИ агент\3060 16 gb\switch-ai.bat" local14-hq
    "D:\ИИ агент\3060 16 gb\switch-ai.bat" cloud
    "D:\ИИ агент\3060 16 gb\switch-ai.bat" cloud-ollama

Проверить, что изменится, ничего не записывая:

    "D:\ИИ агент\3060 16 gb\switch-ai.bat" cloud --dry-run

Только OpenCode (VS Code можно не закрывать) или только Cline:

    "D:\ИИ агент\3060 16 gb\switch-ai.bat" local --opencode-only
    "D:\ИИ агент\3060 16 gb\switch-ai.bat" local --cline-only

Если скрипт запускается не из корня проекта, укажите корень явно:

    "D:\ИИ агент\3060 16 gb\switch-ai.bat" status --root "D:\swiftmatch1bdnoutprodpart1"

Из PowerShell — то же через node (профиль — второй аргумент):

    node "D:\ИИ агент\3060 16 gb\scripts\ai-profile.mjs" status
    node "D:\ИИ агент\3060 16 gb\scripts\ai-profile.mjs" cloud

Коды выхода: 0 — готово, 1 — неизвестный профиль или Cline не записан,
2 — ошибка аргументов/каталога (в том числе запуск из папки комплекта).

Требование: Node.js 22.13 или новее (встроенный node:sqlite работает без флага;
на 22.5-22.12 нужен запуск с --experimental-sqlite). Проверка: node --version.
Без этого OpenCode-часть работает, Cline — нет; скрипт об этом предупредит и
покажет точную причину.

6. ЧТО ИМЕННО МЕНЯЕТСЯ
--------------------------------------------------------------------------------

6.1 OPENCODE — opencode.json

  Скрипт правит только то, что относится к маршруту:

    model          — модель по умолчанию для новых сессий;
    default_agent  — local (без сети, 10 шагов) или cloud;
    providers.ollama.models — описания сборок комплекта и облачного тега
                     (контекст и поддержка инструментов; облачные теги
                     не всегда попадают в автодискавери Ollama);
    agents         — шаблоны агентов local/cloud, если их ещё нет.

  Остальное сохраняется: instructions (persona + AGENTS.md), чужие провайдеры,
  ваши агенты, тема и любые другие ключи. Это мерж, а не замена файла.
  Перед записью создаётся opencode.json.bak-<дата>.

  Ключи — в актуальной форме OpenCode V2: providers, agents, permissions.
  Старые provider / agent / permission OpenCode V2 ещё читает, но они помечены
  устаревшими; новые примеры в 08 и 10 — тоже V2.

  Важно: config читается при старте OpenCode. Уже открытая сессия хранит
  выбранную модель отдельно — переключите её через /models или начните новую.
  Если модель не сменилась даже в новой сессии, перезапустите opencode.

6.2 CLINE — state.vscdb

  Cline хранит провайдера и модель не в settings.json, а в globalState VS Code:

    %APPDATA%\Code\User\globalStorage\state.vscdb
    ключ saoudrizwan.claude-dev

  Скрипт обновляет:

    apiProvider, apiModelId,
    planModeApiProvider, actModeApiProvider,
    planModeApiModelId, actModeApiModelId,
    ollamaModelId, ollamaBaseUrl, ollamaApiOptionsCtxNum,
    planModeOllamaModelId, actModeOllamaModelId

  Авто-одобрение, чекпоинты и остальные настройки НЕ трогаются.

  Требования:

    1) VS Code закрыт. Иначе скрипт откажется писать: VS Code перезапишет
       состояние при выходе. Обойти можно --force, но это риск потери настроек;
    2) после записи открыть VS Code заново: Cline читает состояние при старте;
    3) проверить: Cline -> шестерёнка -> API Configuration;
    4) перед записью создаётся state.vscdb.bak-<дата> рядом с базой.

  Поддерживаются VS Code stable и Insiders; если Cline ещё ни разу не
  запускался, скрипт честно скажет, что state.vscdb не найден.

7. ОБЛАКО: ЧТО ДОЛЖНО БЫТЬ ГОТОВО
--------------------------------------------------------------------------------

Ollama Cloud (Cline и профиль cloud-ollama), вход один раз:

    ollama signin

Проверка живого тега (не угадывать!):

    ollama show gpt-oss:120b-cloud
    ollama run gpt-oss:120b-cloud "ping"

Факт на 30.10.2026 (эта машина, аккаунт авторизован):

    Тег                     Статус
    ----------------------  ----------------------------------------------------
    gpt-oss:120b-cloud      ✅ работает, 131k контекста, tools + thinking
    gemma4:31b-cloud        ✅ работает, 262k контекста, tools + vision (Free)
    deepseek-v4.1-flash:cloud  ⚠ тег есть, запрос вернул 402 Payment Required
    deepseek-v4-pro:cloud   ⚠ тег есть, кредиты не проверялись
    qwen3-coder:480b-cloud  ❌ отозван 15.07.2026 — в старых инструкциях устарел

  Список облачных тегов меняется каждые несколько месяцев. Если тег отозван,
  Ollama подскажет замену в тексте ошибки. Меняется только имя модели:
  профиль, скрипт и правила проекта остаются как есть.

OpenCode (профиль cloud):

    opencode/deepseek-v4.1-flash-free — бесплатная модель облака OpenCode,
    отдельный ключ не нужен. Проверка: /models в OpenCode или opencode models.

DeepSeek / OpenRouter напрямую (необязательно): скрипт их не настраивает, без
ключа это мёртвый профиль. Ключи задаются в окружении (setx) и в репозиторий
не попадают:

    setx DEEPSEEK_API_KEY "sk-..."
    setx OPENROUTER_API_KEY "sk-or-..."

Если Cline пишет про таймаут: облачные модели отвечают дольше локальных,
поднимите таймаут запроса в настройках Cline (Advanced).


--------------------------------------------------------------------------------
8. ДИСЦИПЛИНА ОБЛАЧНОГО РЕЖИМА
--------------------------------------------------------------------------------

  - Авто-одобрение записи файлов и команд в Cline в облаке ДЕРЖИТЕ ВЫКЛЮЧЕННЫМ:
    ошибка дорогой модели на большом репозитории стоит денег и ломает гейты.
  - В облако не отправляются .env, auth.json, дампы БД, выгрузки пользователей,
    переписка из messages/chats и скриншоты с реальными ПДн.
  - Перед вставкой лога в облачный чат прогоните его через очистку (email, UUID,
    телефоны, ключи) — рецепт в 05, раздел «Очистка лога».
  - Коммит делает человек. Локальная модель git add/commit/push не выполняет
    (.clinerules 11.1).
