КУДА ПИСАТЬ КОМАНДЫ И КАК РАЗДЕЛИТЬ 3060 / ОБЛАКО
Комплект 3060 12 ГБ VRAM / 16 ГБ ОЗУ. Дата: 29.10.2026
================================================================================

0. КОРОТКО

  Команды проекта (тесты, гейты, сборка) — в cmd.exe в корне проекта.
  Работа ИИ — в одном из трёх мест: OpenCode (терминал), Cline (панель в
  VS Code), Continue (автодополнение, там вообще не печатают).
  Модель на 3060 — для одной правки в одном файле. Облако — для всего, что
  шире одного файла или где локальная уже ошиблась дважды.


1. ПЯТЬ МЕСТ, КУДА ВВОДЯТСЯ КОМАНДЫ

  1.1 cmd.exe в корне проекта — «команды проекта»
      Открыть: Win+R -> cmd -> Enter, затем
          cd /d D:\swiftmatch1bdnoutprodpart1
      Или в VS Code: Ctrl+` (обратная кавычка) — в рабочем пространстве
      swiftmatch-3060.code-workspace терминал уже настроен на Command Prompt.

      Здесь живут:
          npm.cmd run stage:context          где мы и что открыто
          npm.cmd run stage:preflight        гейты до начала работы
          npm.cmd run task:next -- --local   какая задача следующая
          npm.cmd run task:next -- --route   только решение: local или cloud
          npm.cmd run task:next -- --out tmp\next-task.txt
          npx.cmd eslint src\pages\chats.tsx
          npx.cmd vite build
          node node_modules\vitest\vitest.mjs run src\test\<файл>

      ВАЖНО: в PowerShell пишите npm.cmd / npx.cmd — иначе политика
      исполнения блокирует npm.ps1. Проще сразу cmd.

  1.2 OpenCode (TUI в терминале) — «агент, который правит код»
      Запуск: в том же cmd из корня проекта
          opencode
      Внутри:
          обычный текст         = задача агенту (модель — выбранная в сессии)
          /next                 карточка задачи для 3060 (скрипт + --local)
          /next-cloud           карточка по приоритетам бэклога (облако)
          /models               выбрать модель сессии (Ctrl+X, затем M)
          /agents               выбрать агента (Ctrl+X, затем A; Shift+Tab)
          /reload               перечитать конфиг после правки opencode.json
      Конфиг читается без перезапуска, но /reload не помешает.

      /local и /cloud «из коробки» НЕ существуют: это свои команды, два файла
      в .opencode/commands/ (как их создать — п.3.3). Пока файлов нет,
      OpenCode на такую строку отвечает «команда не найдена».
      Как именно выбирается модель — п.3.6, там же проверенные команды.

  1.3 Cline — панель чата внутри VS Code
      Открыть: Ctrl+Shift+P -> "Cline: Open" (или иконка Cline слева).
      Провайдер и модель — шестерёнка в панели Cline:
          локально:  Provider = Ollama, Base URL = http://localhost:11434,
                     Model = swiftmatch-coder-14b, Context = 12288
          облако:    Provider = DeepSeek (или OpenRouter), свой API-ключ
      Авто-одобрение: только read_file / search_files / list_files.
      Запись файлов и терминал — подтверждать руками, пока не убедитесь,
      что 14B не «фантазирует» правки.

  1.4 Continue — автодополнение, печатать ничего не нужно
      Файл: %USERPROFILE%\.continue\config.yaml (готовый — 06-...yaml).
      Серый текст появляется сам, Tab — принять, Esc — отклонить.
      Модель: swiftmatch-coder-tiny (1.5B), чтобы не занимать VRAM у 14B.

  1.5 VS Code Tasks — кнопка вместо терминала (по желанию)
      Файл .vscode/tasks.json в проекте, запуск Ctrl+Shift+B.
      Даёт одну кнопку «взять задачу и открыть карточку» без набора команд.
      Этот файл в .gitignore (.vscode/*), то есть в git он не попадает.


2. ЧТО ДЕЛАЕТ 3060, А ЧТО ОБЛАКО

  На 3060 (локально, бесплатно, код не уходит наружу):
    + одна правка в одном файле (карточка next-task уже режет до одного файла);
    + «прочитай файл и объясни», поиск места по описанию;
    + мелкий рефакторинг внутри файла, переименования;
    + автодополнение в редакторе (1.5B);
    + запуск тестов/линта/сборки — это вообще не модель, это CPU.

  В облако (DeepSeek через OpenCode):
    + всё, что шире одного файла: новые модули, миграции SQL, схема;
    + разбор красных гейтов и длинных логов;
    + ревью диффа перед коммитом;
    + написание тестов на 200+ строк;
    + планирование этапа (stage:context -> план -> задачи).

  Почему именно так: 14B уверенно держит ~1 файл. Как только задача требует
  помнить 4-5 файлов и вызывать инструменты подряд, она начинает «терять»
  правки — и переделка стоит дороже, чем сэкономленные токены.

  Куда уйдёт конкретная задача, скрипт говорит сам — строкой «Маршрут» в
  карточке (и одной строкой в `--route`). Решение принимается по трём
  признакам: нет цитаты `file:line` -> облако; текст пункта или путь файла
  попал в риск-домен (деньги/Stripe, доступ и секреты, схема БД и миграции,
  деплой и инфраструктура) -> облако; иначе -> 3060 по одному файлу за
  подход. Это ключевые слова, а не оценка сложности: скрипт не читает код,
  поэтому последнее слово за человеком (07, п.6.7).

  ПРАВИЛО ЭСКАЛАЦИИ (простое и проверяемое):
    - локальная модель ошиблась дважды на одной задаче -> /cloud;
    - правка требует видеть больше одного файла СРАЗУ -> /cloud
      (если файлы идут по одному подходу — 3060 справится, карточка режет);
    - задача про деньги/безопасность/схему БД -> сразу /cloud;
    - после эскалации карточка та же, контекст не пересылаем заново.

  Решает это человек, а не модель: Cline и 14B не умеют оценивать свои
  пределы. Что скрипт может сказать заранее — строку «Маршрут» в карточке
  (число подходов или «нужен обзор всех файлов»).

  Чего НЕТ и не будет: автоматического «локальная упала -> само ушло в
  облако». OpenCode так не умеет (в документации такого механизма нет).
  Но выбор модели делается детерминированным заранее: файл команды в
  .opencode/commands/ несёт строку model, поэтому /next всегда идёт на
  3060, а /next-cloud — в облако. Строка за строкой — п.3.6.


3. НАСТРОЙКА OPENCODE НА ДОМАШНЕМ ПК

  3.1 OpenCode берёт модели Ollama сам: если Ollama слушает
      http://127.0.0.1:11434 (порт по умолчанию), то в /models появятся
      ollama/swiftmatch-coder-14b и ollama/swiftmatch-coder-tiny.
      Отдельный провайдер прописывать не нужно.

  3.2 Два агента в opencode.json проекта (рядом с AGENTS.md):

      МЕРЖИТЬ, А НЕ ЗАМЕНЯТЬ. В файле уже есть ключ instructions — он подключает
      правила проекта (persona + AGENTS.md). Если заменить файл целиком примером
      ниже и потерять instructions, агент останется без правил. Полный файл
      «как должно получиться» — 10-Приложения.txt, раздел 3.

      {
        "$schema": "https://opencode.ai/config.json",
        "instructions": [".opencode/persona.md", "AGENTS.md"],
        "model": "ollama/swiftmatch-coder-14b",
        "default_agent": "local",
        "agents": {
          "local": {
            "description": "Основная работа на 3060: один файл, узкая правка",
            "mode": "primary",
            "model": "ollama/swiftmatch-coder-14b",
            "steps": 10,
            "permissions": [
              { "action": "webfetch", "resource": "*", "effect": "deny" },
              { "action": "websearch", "resource": "*", "effect": "deny" }
            ]
          },
          "cloud": {
            "description": "Эскалация: многофайловые задачи, ревью, миграции",
            "mode": "primary",
            "model": "deepseek/deepseek-chat"
          }
        }
      }

      Пояснения:
        model            = что берётся по умолчанию (3060);
        default_agent    = какой агент стартует (local);
        steps: 10        = предохранитель от зацикливания 14B;
        webfetch/websearch deny = локальная модель не ходит в интернет;
        cloud            = тот же OpenCode, но на облачной модели.

      Имя облачной модели подставьте своё — то, что реально подключено у вас
      (посмотрите /models). Если модель не найдена, OpenCode берёт ближайшую
      доступную, поэтому лучше проверить глазами.

  3.3 Две команды для переключения (файлы в .opencode/commands/):

      .opencode/commands/local.md
        ---
        description: Выполнить задачу на локальной модели (3060)
        agent: local
        model: ollama/swiftmatch-coder-14b
        ---
        $ARGUMENTS

      .opencode/commands/cloud.md
        ---
        description: Эскалация в облако
        agent: cloud
        model: <ID облачной модели из /models>
        ---
        $ARGUMENTS

      Работает так:
        /local почисти any в src/pages/chats.tsx      (3060, бесплатно)
        /cloud сверь схему миграций с mysql_schema   (облако)

      Строка model — главная: без неё команда лишь переключает агента, а
      модель остаётся той, что выбрана в сессии. С ней маршрут жёсткий и
      повторяемый (п.3.6).

  3.4 Если облако нужно не агентом, а одной задачей из терминала:
        opencode run --model deepseek/deepseek-chat "<карточка>"
      Флаг --model для run документирован; наличие --agent проверяйте через
      opencode run --help (выдумывать не буду).

  3.5 ВАЖНО: не включайте этот конфиг на машине, где моделей Ollama ещё нет
      (например на ноутбуке). Порядок: сначала 02-Установить-локально.bat,
      проверка ollama list (должны быть swiftmatch-coder-14b и
      swiftmatch-coder-tiny), и только потом правка opencode.json.


  3.6 КАК РЕАЛЬНО ВЫБИРАЕТСЯ МОДЕЛЬ (проверено по документации OpenCode V2)

      Скрипт next-task.mjs модель НЕ выбирает: у него нет ни ключей, ни
      доступа к API, ни памяти «ошиблась дважды». Он решает ЧТО делать и
      режет задачу до карточки (~5 КБ). ГДЕ это делать решают четыре уровня,
      от самого сильного к самому слабому:

        1. model в шапке команды (frontmatter) — перекрывает всё остальное
           Модель задаёт файл команды, а не модель и не скрипт:

             ---
             description: Следующая задача для 3060
             agent: local
             model: ollama/<точный ID из /models>
             ---

           Так /next жёстко уходит на 3060, а /next-cloud — в облако.
           Это и есть детерминированный автовыбор: решение принимает
           конфигурация, один и тот же бэклог даёт один и тот же маршрут.

           В нынешних next.md и next-cloud.md строки model нет — они
           выбирают задачу, а модель берут из сессии. Чтобы маршрут стал
           жёстким, добавьте строку model (ID — из /models) в шапку файла.

        2. model у агента (opencode.json, блок agents)
           Работает, когда у команды своей строки model нет.

        3. /models — модель текущей сессии, вручную
           Меняет только сессию, файл конфига не переписывает.

        4. opencode run --model provider/model "<промпт>" — на один запуск
           Ничего не меняет в конфиге.

      Развилки «Ollama локально ИЛИ OpenCode» не существует. Это два разных
      вопроса:
        • ЧЕМ исполнять — Cline в VS Code или OpenCode в терминале. Оба умеют
          править файлы, оба видят один и тот же проект;
        • НА ЧЁМ считать — локальная модель Ollama на 3060 или облачная.
          OpenCode прекрасно работает на локальной Ollama (он сам её находит,
          см. ниже), а Cline можно направить в облако ключом DeepSeek.
      Скрипт next-task.mjs отвечает только на второй вопрос (local/cloud) и
      печатает это в строке «Маршрут»; чем исполнять — решает человек.

      Про агентов отдельно: переключение агента — /agents (Ctrl+X, затем A,
      Shift+Tab по кругу). Команды «/agents select <имя>» в OpenCode НЕТ.
      И выбранный агент сам модель сессии не меняет — модель берётся
      уровнями 1, 2 или 3.

      Ollama подключать не надо: OpenCode сам находит её на 127.0.0.1:11434
      и показывает модели как ollama/<имя>. Отдельный блок providers не
      нужен. Точный ID брать в /models, а не угадывать: тег Ollama может
      быть частью имени (qwen2.5-coder:14b, у своей сборки — :latest).
      Если ID не совпал, команда отвечает «Model unavailable» и не делает
      ничего, поэтому строку model вписывать только после проверки.

      Облачные модели Ollama (теги -cloud после ollama signin) — это тот же
      провайдер ollama, просто модель считается не на 3060. Для OpenCode это
      такая же запись ollama/<имя>-cloud: отдельного «облачного провайдера»
      нет, и перехода на неё «когда не хватило VRAM» тоже нет.

      Запуск OpenCode сразу на нужной модели Ollama (0.40+):
        ollama launch opencode --model swiftmatch-coder-14b


4. ОДНА ФРАЗА: «ДОДЕЛАЙ ИЗ ЧТО ДОДЕЛАТЬ» — КУДА ВВОДИТЬ

  4.1 OpenCode (терминал):
        /next              узкая задача для 3060 (только file:line)
        /next-cloud        по приоритетам бэклога (для облака)
        /next QA-01        конкретный пункт
      Файлы команд: .opencode/commands/next.md и next-cloud.md.
      В git они не добавлены — лежат в рабочем дереве.
      Модель эти команды не выбирают (строки model в них нет): её берёт
      сессия. Жёсткий маршрут «/next = 3060, /next-cloud = облако» —
      одна строка model в шапке файла, см. п.3.6.

  4.2 Cline (панель в VS Code):
        просто напишите:  Доделай из Что доделать
      Правило в .clinerules (п.10) обязывает агента сначала выполнить
      node scripts/next-task.mjs --local --out tmp/next-task.txt,
      прочитать карточку и работать только по ней.

  4.3 cmd (совсем без модели, только карточка):
        npm.cmd run task:next -- --local
        start tmp\next-task.txt

  Почему нельзя просто «прочитай бэклог и сделай»:
      «Что доделать.txt» ~18 тыс. токенов, контекст 12288. Модель либо
      обрежет файл, либо начнёт выдумывать пункты. Скрипт режет бэклог до
      карточки ~5 КБ, и модель видит ровно одну задачу и один файл.

  Что происходит по шагам:
      1) скрипт выбирает задачу детерминированно (не модель);
      2) печатает карточку: ID, строка бэклога, цитата file:line, один файл,
         гейты, готовый промпт;
      3) агент читает ТОЛЬКО карточку;
      4) показывает план 3-5 пунктов, ждёт «делай»;
      5) правит один файл, гоняет гейты, отчитывается.

  Важно про 3060: команды /next и /next-cloud сейчас без полей agent/model —
  работают на той модели, что выбрана в сессии. После установки моделей Ollama
  добавьте в frontmatter две строки:
      /next:        agent: local     model: ollama/swiftmatch-coder-14b
      /next-cloud:  agent: cloud


5. ПОРЯДОК ПЕРВОГО ДНЯ НА ДОМАШНЕМ ПК

   1) Драйвер NVIDIA: nvidia-smi показывает карту, memory.total = 12 GiB.
   2) Ollama установлена: ollama --version.
   3) 02-Установить-локально.bat -> профиль [1] (14B q4), затем ещё раз -> [4]
      (1.5B для автодополнения).
   4) Закрыть Ollama в трее и запустить заново (переменные окружения).
   5) 03-Замер-скорости.bat -> "eval rate" 25-35 ток/с, ollama ps -> 100% GPU.
      Если 3-5 ток/с — модель не влезла в VRAM, ставьте num_ctx 8192.
   6) ollama list -> есть swiftmatch-coder-14b и swiftmatch-coder-tiny.
   7) VS Code + расширения (Cline, Continue, ESLint, Tailwind).
   8) Открыть swiftmatch-3060.code-workspace.
   9) Скопировать .clinerules в корень проекта.
  10) Вставить блок 3.2 в opencode.json, создать два файла из 3.3.
  11) Проверка связки: открыть cmd в проекте, выполнить
          npm.cmd run stage:context
          npm.cmd run task:next -- --local
      Взять карточку, отдать в Cline (локально) или в /local (OpenCode).
  12) Continue: положить 06-...yaml в %USERPROFILE%\.continue\config.yaml,
      перезапустить VS Code, проверить серые подсказки.


6. ЧЕГО НЕ ДЕЛАТЬ

   - Не запускать npm install / npm ci под живым API (EPERM, полусломанное
     дерево). Сначала остановить стек.
   - Не давать локальной модели задачу «почини весь проект» — она вернёт
     10 файлов с выдуманными правками.
   - Не включать авто-одобрение записи и терминала в Cline на 14B.
   - Не держать в VRAM одновременно 14B и 7B «на всякий случай»: 12 ГБ
     хватает на 14B + 1.5B, третий моделью начнётся CPU/GPU split.
   - Не пересылать в облако .env, ключи, дампы БД. Карточки из next-task
     содержат только пути и текст бэклога — их можно.
