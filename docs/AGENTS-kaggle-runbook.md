# Kaggle: запасной стенд для автосреза

> Ноутбук: `evals/kaggle-agent-live.ipynb`. Назначение — снять те же 7
> read-only задач, когда 3060 занята или недоступна. Канон остаётся на 3060.

## Что понадобится

- Аккаунт Kaggle с подтверждённым телефоном (без него GPU не дают).
- В ноутбуке: **Settings → Accelerator → GPU T4 ×2**,
  **Settings → Internet → On**.
- ~30 GPU-часов в неделю — квота Kaggle, одна сессия съедает 15–30 минут.

## Как запустить

1. Открыть `kaggle.com/code` → **New Notebook**.
2. **File → Import Notebook** → загрузить `evals/kaggle-agent-live.ipynb`.
3. Проверить, что Accelerator = GPU T4 ×2, Internet = On.
4. Выполнять ячейки сверху вниз. Первая ячейка задаёт репозитории, модель и
   рабочий каталог.
5. Последняя ячейка печатает `pass N/7`, среднее шагов и выдуманные файлы;
   JSON копируется в `/kaggle/working` — скачать его оттуда.

## Что делают ячейки

| Ячейка | Действие |
|---|---|
| 1–2 | параметры и переменные окружения (`OLLAMA_HOST=127.0.0.1:11434`) |
| 3 | проверка GPU |
| 4 | Ollama из tgz в `/tmp`, без sudo |
| 5 | `ollama serve` в фоне, ожидание `/api/version` |
| 6 | `ollama pull qwen2.5-coder:14b` и создание `qwen2.5-coder-16k:latest` |
| 7 | Node 20, если его нет в образе |
| 8 | клон комплекта и проекта-полигона |
| 9 | `node scripts/agent-live.mjs --root ... --out ...` |
| 10 | сводка и копия JSON в `/kaggle/working` |

## Модель: что именно воспроизводится

Локальный тег `qwen2.5-coder-16k:latest` — это `qwen2.5-coder:14b` (Q4_K_M,
14.8B) с параметрами `num_ctx 16384`, `temperature 0.2`, `top_p 0.9`.
Ноутбук создаёт такой же тег из `Modelfile`.

Сам `agent-live.mjs` на каждый запрос всё равно передаёт свои
`temperature 0.1`, `num_ctx 12288`, `num_predict 700`, поэтому параметры
модели влияют только на базовую совместимость. Менять базовую модель нельзя:
другие веса — другие числа, сравнивать с `live-2026-10-31-full2.json` будет
нечестно.

## Ограничения

- **7 задач из 10.** E-04/E-05 (правка файла) и E-06 (`git diff`) автосрез не
  проверяет ни здесь, ни локально. Ручной прогон AGT-02 в Cline не заменяется.
- **Числа не идентичны 3060.** Та же модель, но другой рантайм (T4, драйвер,
  версия Ollama). Совпадение вердиктов ожидаемо, совпадение шагов — нет.
- **Сессия умирает.** 12 часов максимум, 60 минут простоя — стоп. Всё, что не
  скачано из `/kaggle/working`, теряется.
- **Диск.** Модель ~9 ГБ лежит в `/tmp/agent-live/models`. Если Kaggle не даёт
  места, поменять `WORK` в первой ячейке на другой каталог.
- **Приватные репозитории.** `git clone` попросит пароль и упадёт. Тогда токен
  из Kaggle Secrets подставляется в URL в первой ячейке; в текст ноутбука
  токен не вписывать.

## Безопасность

- Исходники проекта уезжают на чужую машину. Для закрытого кода — только
  локальный прогон.
- Ollama слушает `127.0.0.1`, наружу не публикуется. Туннель не поднимать.
- Токены — только через Kaggle Secrets, не в ячейках.

## Как вернуть результат

1. Скачать `live-kaggle-<дата>.json` из `/kaggle/working`.
2. Положить в `evals/`.
3. В «Что сделано.txt» указать, что число снято на Kaggle, а не на 3060, и
   какая была модель.
4. Не перезаписывать `evals/live-2026-10-31-full2.json`: это канон с 3060.

## Проверено / не проверено

- Синтаксис bash-ячеек проверен локально (`bash -n`), JSON ноутбука парсится.
- На самом Kaggle ноутбук ещё не запускался: числа T4 и поведение образа
  (наличие Node, размер `/tmp`) не подтверждены. Первый прогон — проверочный,
  его результат и станет фактом.
