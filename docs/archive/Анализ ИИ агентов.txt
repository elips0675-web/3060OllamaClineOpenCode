Краткий разбор: как заставить локальный ИИ-ассистент работать на RTX 3060 12 ГБ
1. Главный вывод: Cline не «тупой» — ему не хватает архитектуры контекста
Ваше ощущение, что Cline «надо постоянно обучать» и он «глупеет», связано не с выбором инструмента, а с тем, что:

у Cline нет встроенной долговременной памяти;

каждая сессия держится на контекстном окне;

локальные модели 7B–14B быстро «задыхаются», когда системный промпт + история + файлы переполняют контекст;

как только контекст переполняется, модель начинает терять правила, ломать формат и вызывать инструменты невпопад.

Поэтому решение — не дообучение 7B до DeepSeek, а инженерия контекста, правильный выбор инструмента и настройка параметров под 12 ГБ VRAM.

2. Какую архитектуру выбрать
Ваша задача	Инструмент	Почему
Работа с существующим кодом: рефакторинг, фичи, багфиксы	Aider	repo map подгружает только нужные файлы, экономит контекст; 14B Q4 стабильно работает на 3060; есть режим --architect (сначала план, потом код)
Автоматизация: cron-задачи, браузер, уведомления	openclose	Skills, Jobs, 14 инструментов из коробки, SQLite локально, без облака
Свой узкий агент под нестандартную задачу	Smolagents	10–20 строк — и у вас свой агент с нужными инструментами
Продолжать ежедневный кодинг в Cline	Cline + Compact Prompts + .clinerules + Memory Bank	Минимальные затраты, но обязательна дисциплина контекста
Чего избегать на 12 ГБ: Devika и OpenHands как основной инструмент — слишком высокое потребление VRAM, будут свопинги и тормоза.

3. Если остаётесь на Cline — сделайте это сразу
Включите Compact Prompts
Настройки Cline → Features → «Use Compact Prompt». Системный промпт сокращается примерно на 90%, локальная модель перестаёт «не дочитывать» инструкции.

Создайте .clinerules/ с конкретными правилами
Не «пиши чистый код», а:

переменные — camelCase, классы — PascalCase;

все I/O в try/catch;

обработка ошибок — как в /src/utils/errors.ts;

перед вызовом инструмента — Confidence Check: если уверенность ниже 7/10, задай уточняющий вопрос.

Подключите Memory Bank
Файл .clinerules/memory-bank.md + команды initialize memory bank в начале и update memory bank в конце сессии. Модель сможет перечитывать состояние проекта из файлов, а не держать всё в голове.

Для сложных задач — /deep-planning
Cline сначала исследует код, задаёт вопросы, создаёт implementation_plan.md, вы утверждаете — только потом код. Меньше переделок.

MCP-серверы по необходимости
Бесплатные варианты: DuckDuckGo MCP (полностью open-source, без ключа), Tavily/Firecrawl (freemium, ~1000 кредитов/мес), Safe-agent-mcp (MIT, локальный аудит). Не ставьте всё сразу — добавляйте под конкретную нехватку.

Разделяйте модели по задачам
7B — для рутины и summarization, 14B — для планирования и рефакторинга.

4. Железные оптимизации под RTX 3060 12 ГБ
Модель и квантование
Сладкая точка: Qwen2.5-Coder-14B-Instruct в Q4_K_M (~8.5 ГБ VRAM). Остаётся ~3.5 ГБ на контекст и систему — хватает на 8K–16K токенов без OOM.

Для 6 ГБ (ноутбук): Qwen2.5-Coder-7B Q4_K_M (~5 ГБ) или Llama-3.2-3B для быстрых рутинных задач.

Избегайте 32B+ в Q2/Q3 — часть слоёв уйдёт в RAM, скорость упадёт с ~30 tok/s до 2–3 tok/s.

Modelfile для Ollama
dockerfile
FROM qwen2.5-coder:14b
PARAMETER num_ctx 8192
PARAMETER num_gpu 999
PARAMETER temperature 0.2
PARAMETER top_p 0.9
Ключевой момент — явно задать num_ctx. Если не задать, Ollama может попытаться выделить память под 32K+ и уронить драйвер или вызвать троттлинг.

Параметры генерации в Cline
Temperature: 0.1–0.3 (для кода нужна детерминированность).

Max Tokens: 2048–4096.

Stop sequences — обязательно, чтобы не было бесконечной генерации.

5. Про «обучение» — честно
Дообучить 7B на 3060 до уровня DeepSeek-V3/Coder-V2 физически невозможно: это модели на сотни миллиардов параметров, обученные на суперкомпьютерах.

Что реально работает:

Метод	Сложность	Нагрузка на 3060	Качество	Стоимость
Бесплатный API DeepSeek (OpenRouter, GitHub Models)	Очень низкая	0%	Максимальное	$0 в рамках лимитов
.clinerules + few-shot + RAG	Низкая	Обычная	Высокое	$0
QLoRA через Unsloth + бесплатный Colab (T4/A100)	Высокая	Локально 0	Среднее, зависит от датасета	$0
Практический совет: если хочется «умнее» без облака — сначала пробуйте контекстную инженерию. Если всё же нужен fine-tune — делайте его в Colab через Unsloth, экспортируйте в GGUF и возвращайте на 3060. Локально на 12 ГБ训练 7B — путь к мучениям.

🏆 Почему agentkai — формально «комбайн»
Он действительно объединяет в одном агенте всё, что вы перечислили:

Кодинг и файлы: инструменты для работы с оболочкой и файловой системой с ограничением по root-доступу и блок-листом.

Терминал: те же shell-инструменты с системой разрешений (allow/ask/deny) по уровню риска.

Браузер: настоящий экземпляр Chromium для автономной работы.

Задачи по расписанию: встроенный планировщик с поддержкой cron, one-shot задач и «heartbeat»-проверок.

Долговременная память: нативные файлы SOUL.md, USER.md, MEMORY.md в виде обычного Markdown, который можно читать и редактировать вручную.

Плюс бонусы вроде шлюзов в Telegram/Discord и 12 встроенных навыков (Gmail, GitHub и т.д.). Это именно тот набор, который вы искали.

🆚 Где Iridium и AgenticSeek проигрывают по вашему же списку
Iridium Agent — великолепный «комбайн для разработчика»: полноценная веб-IDE, встроенный терминал node-pty, собственный Chromium и даже запланированные фоновые задачи. Но его память — это скорее механизм для сессионной работы и чекпоинтов, а не та долговременная память проекта (MEMORY.md), которую вы хотите. Планировщик есть, но он не является основной философией инструмента.

AgenticSeek — это «комбайн-эксперимент». Он умеет и кодить, и бродить по вебу, и планировать, но у него нет встроенного cron-планировщика и файловой долговременной памяти в том же смысле. Плюс, как вы верно отметили, это прототип, который на полном цикле быстро «захлебнётся» контекстом на 14B-модели.

⚠️ Главная ловушка, о которой стоит помнить
Ваш анализ про VRAM абсолютно точен. Наличие 15 инструментов у agentkai не означает, что модель может эффективно держать их все в голове одновременно. Когда вы даёте задачу, описания всех доступных инструментов могут загружаться в контекст. Для Qwen2.5-Coder-14B в Q4 (≈8.5 ГБ на веса) плюс системный промпт и описания инструментов (≈2–3 ГБ) остаётся очень мало места на историю диалога.

Секрет успеха — использовать его не как «швейцарский нож с открытыми лезвиями», а как ящик с инструментами: через строгие правила или настройки давать агенту только тот инструмент, который нужен для текущей задачи. В agentkai это частично решается через permission-gated доступ и «навыки», но дисциплина контекста всё равно остаётся на вас.
