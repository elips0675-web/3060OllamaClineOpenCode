# OpenClose: эксперимент на 3060

> Внешний харнесс, не часть комплекта. Здесь только результаты проверки и
> выводы. Сам OpenClose лежит в `E:\openclose` и в этот репозиторий не
> коммитится.

## Стенд

- Дата: 31.10.2026.
- OpenClose 1.0.1, commit `f65af30`.
- RTX 3060 12 ГБ, Ollama 0.20.5.
- Python 3.12.16 через `uv` 0.13.6 (системный Python 3.14 не использовался).
- Модель: `qwen2.5-coder-16k:latest`.
- Конфиг: `%APPDATA%\openclose\config.toml`.
  - provider `ollama`, `base_url = http://127.0.0.1:11434/v1`;
  - `max_context_tokens = 12288`, `compaction_threshold = 0.8`;
  - `temperature = 0.1` для `build` и `plan`;
  - permissions: `read`, `grep`, `glob`, `delegate`, `plan` — allow,
    остальное — deny;
  - кастомный агент `local-readonly` с русским системным промптом комплекта.

## Главная находка: у локальных моделей нет нативных tool_calls

Проверены через `/api/chat` с массивом `tools`:

- `qwen2.5-coder-16k:latest`
- `qwen2.5-coder:14b-instruct`
- `qwen2.5-coder:14b`
- `qwen2.5-coder:7b`
- `servicedesk-qwen-14b:latest`
- `servicedesk-qwen-q5:latest`

У всех `message.tool_calls: null`; модель пишет JSON в `content`:

```json
{"name": "read", "arguments": {"path": "./package.json"}}
```

OpenClose без патча считает такой текст финальным ответом и **не выполняет
инструмент**. Это не проблема OpenClose, а реальность локальной 14B.

## Локальный патч

В `E:\openclose\src\openclose\agent\loop.py` добавлен
`_extract_text_tool_calls()`: он разбирает `<tool_call>...</tool_call>` и
JSON-объекты в тексте, проверяет имя инструмента по списку доступных и
превращает их в `ToolCall`. Без патча эксперимент невозможен.

Патч не upstream: при обновлении OpenClose его нужно перенести заново.
Альтернатива — модель с настоящими `tool_calls` (облачная или другая сборка).

## Вывод

1. **Фичи OpenClose реальны:** `plan`/`delegate`, permissions, compaction,
   SQLite, OpenAI-compatible provider. Это ровно те дыры, которые есть у
   комплекта.
2. **Но «ум» не появляется:** 14B всё равно плохо держит многофайловый анализ
   и цитаты. Патч только позволяет харнессу вообще вызывать инструменты.
3. **Правила комплекта не подхватываются автоматически:** OpenClose не читает
   `.clinerules`. Их надо переносить в `system_prompt` кастомного агента или
   в skill.
4. **Пока OpenClose не лучше нашего `agent-live`:** тот уже умеет fallback
   JSON, проверяет цитаты и считает pass/fail. OpenClose даёт план, права и
   сжатие — их и надо оценивать отдельно, а не по «магии».
