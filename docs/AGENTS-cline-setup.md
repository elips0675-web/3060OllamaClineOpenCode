# Настройка Cline под локальную 14B

> Это настройки инструмента, а не код проекта. Без них правила лежат в
> `.clinerules`, но модель не получает их в нужном объёме: полный системный
> промпт Cline съедает контекст 12288 быстрее, чем файл задачи.

## 1. Compact Prompt

- Откройте настройки Cline (⚙) → **Features** → включите **Use Compact
  Prompt**.
- Если пункта нет в вашей версии — обновите расширение; в старых сборках
  компактного промпта нет.
- Проверка: в новом чате попросите «перечисли свои правила одной строкой».
  Если ответ содержит блоки `RESTATE → MAP → PLAN → ACT → VERIFY → REPORT`,
  правила прочитаны. Если нет — `.clinerules` лежит не в корне проекта.

## 2. Параметры генерации

| Параметр | Значение | Зачем |
|---|---|---|
| Context window | `12288` | 14B Q4 на 12 ГБ; выше — риск CPU/GPU split |
| Max output tokens | `2048–4096` | длинный ответ обрезается, а не съедает VRAM |
| Temperature | `0.1–0.3` | код и цитаты, а не «творческий» пересказ |
| Top P | `0.9` | оставить, если поле есть |
| Stop sequences | `<|im_end|>`, `<|endoftext|>` | если поле есть; Ollama обычно добавляет сам |

Правило: не поднимать context выше 16384 без `ollama ps` — если модель ушла
в RAM, скорость падает с 25–35 до 3–5 ток/с.

## 3. Confidence Check

Добавьте в проектный `.clinerules` (или используйте `40-agent-cycle.md`):

```text
Перед первым инструментом оцени уверенность в том, что понял задачу и
нашёл правильный файл, по шкале 0–10.
- 7–10: действуй по циклу.
- 4–6: задай один уточняющий вопрос.
- 0–3: остановись, перечисли, чего не хватает, и предложи облако.
```

Это не заменяет проверку: модель может быть уверена и ошибаться. Confidence
Check нужен, чтобы она чаще останавливалась до правки, а не после.

## 4. Маршрут моделей

| Задача | Профиль |
|---|---|
| одна правка в одном файле, объяснение файла | локальная 14B (`local`) |
| рутина, автодополнение, быстрый поиск | 7B (`local-q5` / `local7`) |
| больше одного файла, SQL и схема, миграции, ревью диффа | облако (`cloud`) |

Переключение — `switch-ai.bat local` / `switch-ai.bat cloud` из корня проекта.
Cline при закрытом VS Code, OpenCode — новая сессия или `/models`.

## 5. Memory Bank

Шаблоны `cline_docs/` создаёт установщик:

```bat
node "E:\3060OllamaClineOpenCode-main\scripts\init-project.mjs" --root . --dry-run
node "E:\3060OllamaClineOpenCode-main\scripts\init-project.mjs" --root .
```

Порядок работы:

1. **initialize** — прочитать все `cline_docs/*.md`, заполнить
   `projectBrief.md`, `techContext.md`, `systemPatterns.md`; в
   `activeContext.md` записать текущую задачу и план.
2. **update** — в конце каждой задачи обновить `activeContext.md` (что
   сделано, следующий шаг) и `progress.md` (что проверено, что нет).
3. **archive** — устаревшие решения не удалять молча: перенести в
   `cline_docs/archive/` с датой.

Не хранить в `cline_docs/` секреты, токены и персональные данные.

## 6. Проверка после настройки

- [ ] Compact Prompt включён.
- [ ] Context 12288, max output 2048–4096, temperature 0.1–0.3.
- [ ] `.clinerules/40-agent-cycle.md` и `50-few-shot.md` на месте.
- [ ] `cline_docs/activeContext.md` заполнен.
- [ ] Cline отвечает на «где монтируются роуты?» с `file:line`, а не общими
      словами.
- [ ] `switch-ai.bat status` показывает локальную модель.
- [ ] `ollama ps` — `100% GPU`.

## 7. Чего не делать

- Не включать одновременно полный и компактный промпт «для надёжности».
- Не ставить temperature выше 0.4 для правок кода.
- Не давать локальной модели `git push`, миграции и живую БД.
- Не считать «зелёный линт» доказательством корректности: нужен тест и diff.
