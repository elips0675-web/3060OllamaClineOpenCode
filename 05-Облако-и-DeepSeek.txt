================================================================================
ОБЛАКО И DEEPSEEK: КАК ДОБАВИТЬ «УМ» СВЕРХ ЛОКАЛЬНОЙ 14B
================================================================================
Локально = без лимитов, без интернета, код не уходит никуда.
Облако = заметно умнее на многофайловых задачах, но платно/по кредитам,
и содержимое файлов уходит на чужой сервер. Держим оба режима и переключаемся.

--------------------------------------------------------------------------------
ВАРИАНТ 1. OLLAMA CLOUD (самый простой: тот же localhost:11434)
--------------------------------------------------------------------------------
Вход выполняется один раз, модели НЕ скачиваются, идут через облако:

    ollama signin
    ollama run qwen3-coder:480b-cloud "напиши debounce на TypeScript"

Что доступно (облачные теги, октябрь 2026):
    qwen3-coder:480b-cloud    256k контекста, сильный агентный кодер
    deepseek-v4.1-flash       быстрый и дешёвый, только как :cloud
    deepseek-v4-pro           дороже и умнее
    gpt-oss:120b-cloud        альтернатива от OpenAI

ВАЖНО: список облачных тегов в Ollama меняется каждые несколько месяцев
(модели появляются, переименовываются и уходят). Эти четыре строки — снимок
на дату комплекта, а не гарантия. Перед настройкой всегда проверяйте живой
список:  ollama.com/library  (облачные теги помечены -cloud), либо живой
список моделей после ollama signin. Если указанного тега нет, берите любую
доступную -cloud модель: меняется только строка ollama run и поле Model ID
в Cline, всё остальное в комплекте остаётся как есть.

В Cline ничего перенастраивать не нужно:
    API Provider: Ollama
    Base URL:     http://localhost:11434
    Model ID:     qwen3-coder:480b-cloud

Плюсы: один провайдер на два режима, локальные модели остаются на месте.
Минусы: нужен интернет; на бесплатном тарифе — стартовые кредиты и ограничение
на число параллельных запросов, дальше платно по кредитам. Тарифы и лимиты
меняются: цифры смотрите на ollama.com/pricing, в комплекте они не фиксируются
(на 30.10.2026 не подтверждались).

Для вашей машины это плюс и по памяти: облачная модель не грузится в 12 ГБ VRAM
и не занимает 16 ГБ ОЗУ, поэтому рядом с облаком можно держать браузер и API.

Проверка связи:
    curl http://localhost:11434/api/tags


--------------------------------------------------------------------------------
ВАРИАНТ 2. DEEPSEEK НАПРЯМУЮ (OpenRouter или API DeepSeek)
--------------------------------------------------------------------------------
В Cline:
    API Provider: OpenRouter  (или "OpenAI Compatible")
    Base URL:     https://openrouter.ai/api/v1
    API Key:      ключ из переменной окружения, не из файла
    Model ID:     точное имя брать на openrouter.ai/models
                  (например deepseek/deepseek-chat или deepseek/deepseek-v4.1-flash)

Переменная окружения (Windows, один раз):
    setx OPENROUTER_API_KEY "sk-or-..."

Плюсы: самая сильная связка для задач «прочитай 5 файлов, прогони гейты, закоммить».
Минусы: платно по токенам; лимиты провайдера; код уходит наружу.


--------------------------------------------------------------------------------
ВАРИАНТ 3. OPENCODE + DEEPSEEK (второй агент, уже настроен в проекте)
--------------------------------------------------------------------------------
В репозитории уже есть opencode.json:

    { "instructions": [".opencode/persona.md", "AGENTS.md"] }

То есть OpenCode читает правила проекта сам (персона + AGENTS.md) и НЕ нуждается
в .clinerules — дублировать правила не надо, иначе получится третья протухающая
копия, которую ловит гейт check:docs.

Настройка ключа (один раз):
    opencode auth login        -> выбрать DeepSeek -> вставить ключ

Запуск в корне проекта:
    cd D:\swiftmatch1bdnoutprodpart1
    opencode

ВАЖНО, если ключ кладёте в переменную окружения: у OpenCode V2 есть общий
фоновый сервер, и ключ читает он, а не окно терминала. Переменная, выставленная
в новом cmd (set /p OPENROUTER_API_KEY=...), до уже запущенного сервера не
доедет, и облачная модель будет «недоступна». Рабочие способы:
    (а) opencode auth login (в TUI — /connect): ключ ложится в хранилище
        OpenCode (%USERPROFILE%\.local\share\opencode\auth.json);
    (б) переменная окружения или строка в .env проекта, заданная ДО запуска
        opencode (ключи читаются из env и из .env проекта);
    (в) перезапустить opencode после смены переменной — сервер подхватит её
        при старте.
Флагов --standalone и команды opencode service set env в текущем CLI нет
(проверено по документации 29.10.2026) — если встретите их в старых
инструкциях, они устарели.

Локальный вариант через OpenCode (без облака):
    ollama launch opencode --model swiftmatch-coder-14b

Плюсы: сильная модель + правила проекта + гейты, ничего не надо дописывать.
Минусы: интернет, деньги, код на сервере провайдера.

КАК ПЕРЕКЛЮЧАТЬСЯ, НЕ ПЕРЕПУТАВ РЕЖИМЫ
--------------------------------------------------------------------------------
Вариант «профили Cline» (в свежих версиях):
  профиль "local"  -> Ollama + swiftmatch-coder-14b  (работает без сети)
  профиль "cloud"  -> Ollama + qwen3-coder:480b-cloud, либо OpenRouter + DeepSeek
  Переключение — один клик, правила .clinerules общие.

Вариант «два workspace» (если профилей нет):
  swiftmatch-3060.code-workspace        локальный, офлайн
  swiftmatch-3060-cloud.code-workspace  облачный (сделайте копию и поменяйте
                                        провайдера один раз)

Дисциплина: облачный профиль НЕ включать авто-одобрение на запись и команды.
Ошибка дорогой модели на большом репозитории стоит денег и ломает гейты.


--------------------------------------------------------------------------------
ЧТО НЕЛЬЗЯ ОТПРАВЛЯТЬ В ОБЛАКО (это дейтинг, там ПДн пользователей)
--------------------------------------------------------------------------------
  .env и любые файлы с ключами (JWT_SECRET, STRIPE_SECRET_KEY, SMTP, AWS)
  дампы БД (mysqldump) и выгрузки пользователей
  скриншоты админки с реальными email/телефонами
  переписка пользователей из таблиц messages/chats
Перед отправкой файла агенту в облачном режиме: убедитесь, что там нет секретов.
Ключ, случайно попавший в переписку, считается утёкшим — перевыпускайте.


--------------------------------------------------------------------------------
ОЧИСТКА ЛОГА ПЕРЕД ОТПРАВКОЙ В ОБЛАКО (когда ошибка непонятная)
--------------------------------------------------------------------------------
Прежде чем вставлять лог в облачный чат, прогоните его через замену — email,
UUID, телефоны и ключи в логе не нужны ни одной модели:

  PowerShell, из папки с логом:

    (Get-Content app.log -Raw) `
      -replace '[\w.+-]+@[\w-]+\.[\w.]+','[EMAIL]' `
      -replace '[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}','[UUID]' `
      -replace '(?:\+7|8)[\s(-]*\d{3}[\s)-]*\d{3}[\s-]*\d{2}[\s-]*\d{2}','[PHONE]' `
      -replace '(sk|pk|whsec)_[A-Za-z0-9_]{8,}','[KEY]' `
      -replace '(password|token|secret)["'']?\s*[:=]\s*\S+','$1=[HIDDEN]' `
      | Set-Content app.clean.log

  Проверено на тестовом логе: email, UUID, оба формата телефона (+7 999 … и
  8 (999) …) и sk_live_… заменяются, а даты 2026-10-29 10:00:01 и ISO-метки
  остаются целыми (простая маска «много цифр подряд» съедала время в логе).

  Затем читать app.clean.log глазами (не вслепую) и только его отдавать
  в облако. В cmd то же самое делает любой редактор с regex-заменой
  (VS Code: Ctrl+H -> .* -> включить regex).

Важно: это грубая замена, гарантии она не даёт. Правило проще и надёжнее —
в облако идёт фрагмент кода и текст ошибки, а не лог целиком; ПДн, дампы
и .env не идут никогда. Если в логе остался один email — это уже утечка.


--------------------------------------------------------------------------------
МИНИМАЛЬНАЯ ПРОВЕРКА, ЧТО ОБЛАКО РАБОТАЕТ
--------------------------------------------------------------------------------
1. ollama signin  -> "Signed in"
2. ollama run qwen3-coder:480b-cloud "ping"   -> ответ за 2-5 с
3. В Cline: Model ID с суффиксом -cloud, вопрос "сколько файлов в src/pages" —
   агент должен вызвать search_files и ответить.
4. Если Cline пишет про таймаут: облачные модели отвечают дольше локальных,
   поднимите таймаут запроса в настройках Cline (Advanced).
