29.10.2026. АВТООПРЕДЕЛЕНИЕ «ЛОКАЛЬНО / ОБЛАКО» УСИЛЕНО
================================================================================

Вопрос был: «можно ещё улучшить автоопределение — делать в Ollama локально или
через OpenCode?» Ответ по сути: это не развилка. Развилка одна — НА ЧЁМ считать
(локальная модель 3060 или облачная). А ЧЕМ исполнять (Cline в VS Code, OpenCode
в терминале, Continue для автодополнения) — отдельный выбор: OpenCode прекрасно
работает на локальной Ollama, он сам находит её на 127.0.0.1:11434 и показывает
модели как ollama/<имя>. Cline точно так же можно направить в облако ключом.

Что изменено в scripts/next-task.mjs (проект SwiftMatch):

1. routeFor теперь решает по трём признакам, в порядке приоритета:
     1) нет цитаты file:line                       -> cloud (правило проекта);
     2) текст пункта или путь файла попал в
        риск-домен                                  -> cloud;
     3) иначе                                      -> local, по одному файлу
                                                      за подход.
   Риск-домены (новая функция riskyDomain, экспортируется):
     money   Stripe, платёж, подписка, premium, оплата, возврат средств,
             refund, выплата, комиссия, invoice, billing;
     access  JWT, OAuth, auth, CSRF, adminAuth, секрет, токен, уязвимость,
             IDOR, rate-limit, пароль, sanitiz, XSS, SQL-инъекция;
     schema  миграция, mysql_schema, ALTER/CREATE TABLE, ENUM, CHECK, schema,
             схема, индекс;
     infra   docker, compose.yaml, deploy.yml, nginx, деплой, kubernetes.
   Причина печатается в карточке явно: «облако (/next-cloud): <домен> — 14B
   тут ошибается молча; скрипт смотрит ключевые слова, сложность он не
   оценивает».

2. Новый флаг --route: печатает ровно одну строку `local<TAB>текст` или
   `cloud<TAB>текст`, карточку не печатает. Пример живого прогона:
     node scripts/next-task.mjs --route
       local   3060 по одному файлу, подходов: 4 (если нужен обзор всех
               сразу — /next-cloud)
     node scripts/next-task.mjs --id ENV-01 --include-blocked --route
       cloud   облако: нет цитаты file:line, по правилу проекта такой пункт
               не берут

3. --local теперь фильтрует через routeFor, а не только по цитате: пункты
   риск-домена в режим «для 3060» не попадают.

4. В --json добавлено поле route = { target, reason, text }; reason — одно из
   no-citation / money / access / schema / infra / single-file / stepwise.

5. Честная граница записана и в карточке, и в документах: маршрут — это
   ключевые слова, а не оценка сложности. Ложные срабатывания возможны в обе
   стороны («токен» в тексте отправит задачу в облако; тяжёлый рефакторинг без
   таких слов останется локальным). Автоматического «упало локально — ушло в
   облако» нет и не планируется: скрипт только печатает решение, запуск модели
   делает человек.

Проверено:
  • scripts/next-task.test.mjs — 46 тестов (было 38): платежи, доступ, схема,
    инфра, ключевое слово в пути файла, честность формулировки, фильтр --local;

  • npx.cmd eslint scripts/next-task.mjs scripts/next-task.test.mjs — exit 0;
