УНИВЕРСАЛЬНЫЙ ПРОМТ АВТО-ЭТАПОВ (комплект E:\3060OllamaClineOpenCode-main)
================================================================================

Назначение: один текст, по которому агент сам ведёт этапы — берёт пункт,
доводит до зелёных гейтов, пишет журнал, закрывает бэклог, коммитит и
предлагает следующий. Номера строк, счётчики и списки файлов в промт не
вписываются: они протухают. Источник правды — «Что доделать.txt»,
«Что сделано.txt» и прогон гейтов.

--------------------------------------------------------------------------------
ПРОМТ (копировать целиком)
--------------------------------------------------------------------------------

Продолжаем комплект E:\3060OllamaClineOpenCode-main по «Что доделать.txt».

Сначала, до любых правок:
1) Прочитай AGENTS.md — разделы 2 (бюджет), 4 (доказательства), 5 (бэклог),
   5.1 (конец этапа) и 6 (гейты). Полные правила — .clinerules.
2) node scripts/next-task.mjs --local --out tmp/next-task.txt — карточка
   следующего пункта. Если он blocked или watch — не бери его: зафиксируй
   причину и переходи к следующему. --id <ID> берёт конкретный пункт.
3) Проверь, что рабочее дерево чистое: git status --porcelain. Грязное дерево
   сначала разбери, потом начинай этап.

Задача этапа:
- Бери ОДИН пункт. Крупный дроби на смысловые блоки, один блок = один этап.
- Пункт без цитаты file:line не бери: сначала найди файл и строку в коде,
  впиши в пункт, потом работай.
- Работай только в комплекте. Чужие папки — read-only и только с разрешения
  владельца в текущей сессии. Свой бэклог в чужой проект не писать.

Правила этапа:
- Один подход = один файл из раздела «СРЕЗ ДЛЯ ОДНОГО ПОДХОДА» и ≤ 3 файла /
  ≤ 60 КБ входа. Больше — дроби на этапы или отдай облаку.
- Каждое утверждение о коде — file:line из прочитанного файла. .md, .txt, логи
  и отчёты доказательством не являются.
- Кириллические .txt/.md правь node-скриптами (readFileSync/writeFileSync,
  utf8, сохранять EOL), не через PowerShell. npm/npx — через npm.cmd/npx.cmd.
- test/ не пересобирать: node test/build-pack.mjs --check намеренно даёт
  расхождение до отдельного разрешения.
- Две неудачи подряд по одному месту — стоп и эскалация в облако, а не третий
  заход.
- Риск-домен по 11.2 .clinerules: правка денег, доступов, схемы БД, миграций,
  деплоя — облако, даже если файл один.

Гейты этапа (все exit 0, команды проекта — из карточки):
    npm.cmd test
    npm.cmd run check:backlog
    npm.cmd run docs:check
    npm.cmd run retent:check
Красный гейт разбирается по выводу. «Ещё разок» без правки — не считается.

КОНЕЦ ЭТАПА (правило владельца, без исключений):
Этап не считается сделанным, пока не сделаны ВСЕ четыре шага. Если хоть один
не сделан — этап не закрыт, и в отчёте это написано прямо.

1) «Что сделано.txt» — запись СВЕРХУ, коротко: ID, что сделано, команда,
   вывод, что не проверено. Дата — в заголовке записи.
2) «Что доделать.txt» — факт дописан в пункт, если он остаётся; если пункт
   закрыт, он удаляется целиком через node scripts/backlog.mjs close --id <ID>.
   Строку «ЗАКРЫТО» в бэклоге не оставлять — это FAIL гейта.
3) Гейты выше — все exit 0.
4) Git — git add только затронутых файлов, git commit с сообщением без
   тире и вертикальной черты, git push origin main. После этапа
   HEAD == origin/main и git status --porcelain пуст.

Порядок именно такой: журнал и бэклог — до коммита, чтобы одним коммитом
уходили и правка, и её след в журналах. Коммит без записи в журнал и без
правки бэклога считается незавершённым этапом.

Формат ответа: что сделано (с file:line), какие гейты прошли, что не проверено,
и блок «Предлагаю дальше» — следующий незаблокированный пункт с причиной.

--------------------------------------------------------------------------------
ЧТО СЧИТАТЬ БЛОКЕРОМ
--------------------------------------------------------------------------------

- Нужен GUI (VS Code, Cline, Continue Tab) — этап не делается агентом.
- Нужны права администратора (лимит мощности GPU и т.п.) — только фиксировать.
- watch — ждёт решения владельца; без решения не начинать.
- Нужен реальный чужой проект — брать только read-only и с разрешения.
