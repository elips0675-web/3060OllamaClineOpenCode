ВАША КОНФИГУРАЦИЯ (подтверждена владельцем)
--------------------------------------------------------------------------------
  GPU:  RTX 3060, 12 ГБ VRAM
  ОЗУ:  16 ГБ
  Вывод: профиль A — qwen2.5-coder:14b q4_K_M, ctx 12288.
  Папка называется "3060 16 gb" по объёму ОЗУ; видеопамяти — 12 ГБ.

Проверка одной командой (для отчёта и на будущее):

    nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv

Должно быть memory.total = 12 GiB. Если меньше (8 GiB) — берите профиль C.

Что даёт 16 ГБ ОЗУ, а что запрещает
  Разрешает: 14B q4 (~9 ГБ) целиком в VRAM + 1.5B (~1 ГБ) на автодополнение.
    Итого ~10 ГБ VRAM из 12, ОЗУ занята только Windows, VS Code и браузером.
  Запрещает: 14B q6/q8 и qwen3-coder:30b (19 ГБ) — это уже в ОЗУ, то есть
    "CPU/GPU split" и 3-5 ток/с вместо 30.
  Требует: не открывать одновременно Chrome на 30 вкладок, VS Code, Cline,
    MySQL, API и Vite preview. При 16 ГБ это реально ~7-8 ГБ, и первый
    запуск модели (она читается с диска в VRAM) лучше делать при закрытом
    браузере. Файл подкачки Windows не отключать.

Важно: модель обязана поместиться в VRAM ЦЕЛИКОМ. Как только Ollama начинает
выгружать слои в ОЗУ (в `ollama ps` видно "CPU/GPU split"), скорость падает с
30 ток/с до 3-5 ток/с. Проверка после первого запуска:

    ollama ps
    NAME                       ID     SIZE     PROCESSOR    UNTIL
    swiftmatch-coder-14b  ...    10 GB    100% GPU     30 minutes

Должно быть "100% GPU". Если нет — уменьшайте num_ctx или берите квант легче.
Для вашей карты ориентир: 14B q4 при ctx 12288 занимает ~10.1 ГБ, остаётся
~1.9 ГБ на десктоп Windows и CUDA. Если split всё равно появился — первым делом
поставьте num_ctx 8192 (KV-кэш падает с ~1.1 до ~0.75 ГБ).

ПОРЯДОК ДЕЙСТВИЙ (30-60 минут, из них 20 — скачивание моделей)
--------------------------------------------------------------------------------
1. Драйвер NVIDIA. Проверьте: nvidia-smi работает и показывает карту.
   Если нет — поставьте драйвер с сайта NVIDIA (нужен интернет, один раз).

2. Ollama. Установлена? Проверьте: ollama --version.
   Если нет — https://ollama.com/download (Windows installer).

3. Запустите 02-Установить-локально.bat, выберите профиль [1] (3060 12 ГБ).
   Скрипт скачает базу (~9 ГБ) и соберёт модель с правильным контекстом.
   Затем запустите скрипт ещё раз и выберите [4] — маленькую модель для
   автодополнения (1 ГБ).
   После этого ЗАКРОЙТЕ Ollama в трее и запустите снова — иначе новые
   переменные окружения не подхватятся.

4. Проверьте, что модель на GPU: 03-Замер-скорости.bat  -> строка "eval rate".
   Ожидаемо: 25-35 ток/с у 14B q4, 45-55 у 7B q8. Если 3-5 — модель не влезла.

5. VS Code: установите расширения (пока есть интернет!)
       code --install-extension saoudrizwan.claude-dev
       code --install-extension Continue.continue
       code --install-extension dbaeumer.vscode-eslint
       code --install-extension bradlc.vscode-tailwindcss

6. Откройте swiftmatch-3060.code-workspace (двойной клик).
   В нём уже: терминал = Command Prompt, исключены node_modules/dist, указан TS SDK.

7. Скопируйте .clinerules в корень проекта SwiftMatch (рядом с AGENTS.md).
   Cline читает его при каждом запросе и не даёт агенту нарушать правила проекта.

8. Настройте Cline: провайдер Ollama, Base URL http://localhost:11434,
   Model ID = swiftmatch-coder-14b, Context Window 12288 (профиль A) или
   16384 (профиль B). Авто-одобрение — только read_file / search_files / list_files.

9. Один раз проверьте связку на узкой задаче: «прочитай src/pages/chats.tsx,
   покажи 3 места с any, ничего не меняй». Если агент отвечает за 20-40 секунд —
   всё настроено верно. Если за 5 минут — модель ушла на CPU, вернитесь к шагу 4.

10. Continue.dev (автодополнение): положите 06-Continue-автодополнение.yaml в
    %USERPROFILE%\.continue\config.yaml и перезапустите VS Code.

11. Переключение профилей (локально ↔ облако) — одной командой из корня проекта:
        "D:\ИИ агент\3060 16 gb\switch-ai.bat" status
        "D:\ИИ агент\3060 16 gb\switch-ai.bat" local-q5
        "D:\ИИ агент\3060 16 gb\switch-ai.bat" cloud
    Скрипт меняет модель сразу в Cline и OpenCode. Перед профилем Cline
    закройте VS Code; в OpenCode выберите модель в /models или начните новую
    сессию. Профили, Q4/Q5/Q8 и живые облачные теги — в 12-Переключение-моделей.txt.
    Требуется Node.js 22.13+ (встроенный node:sqlite без флага — для записи
    настроек Cline).

12. Анализ проекта по фактам (а не «по шаблону»): из корня проекта
        node "D:\ИИ агент\3060 16 gb\scripts\project-brief.mjs" --root .
    Бриф печатает карту (точки входа, роуты, БД, тесты, крупные файлы,
    TODO/FIXME), но доказательством не является: модель обязана прочитать
    3-6 файлов целиком и цитировать file:line. Итог — карточка
    templates/analysis-card.md; правила — templates/analysis-rules.md.
    Подробно — 13-Анализ-проекта.txt.

13. Бэклог и журнал живут по механизму проекта: открытый пункт — с ID и датой
    проверки, закрытый уходит в «Что сделано.txt», в бэклоге остаётся одна
    строка ✅. Проверка и закрытие:
        npm.cmd run check:backlog
        npm.cmd run backlog:close -- --id BLK-01 --ref "раздел «BLK-01»"
    Правила — в конце «Что доделать.txt».

14. Агентный контур: протокол шага (templates/agent-protocol.md) копируется в
    проектный .clinerules, workflows — в .clinerules/workflows, Memory Bank — в
    cline_docs. После каждой правки правил снимайте балл на 10 задачах:
        npm.cmd run eval:list
        npm.cmd run eval:record -- --id E-01 --pass --steps 4 --fabricated 0
        npm.cmd run eval:score -- --strict
    Порог: pass >= 7/10, выдумано 0, среднее шагов <= 6. Ниже — править правила
    по фактам провалов, а не браться за LoRA. Подробно — evals/README.md.


ЧЕСТНЫЕ ОГРАНИЧЕНИЯ 14B НА 3060
--------------------------------------------------------------------------------
- 14B — это не DeepSeek и не Claude. Многофайловые задачи с длинной цепочкой
  рассуждений она проваливает чаще. Рабочая схема: локально — узкие правки и
  «прочитай/объясни», облако — большие задачи из бэклога.
- Контекст 12-16k токенов. Проект большой, поэтому правило простое: не давать
  агенту читать репозиторий целиком, только конкретные файлы.
- Качество 14B q4 заметно ниже 14B q6/q8. Если VRAM позволяет — профиль B.
- Скорость prefill на 3060 ~200-400 ток/с, это нормально: агент «думает» секунды,
  а не минуты, как на ноутбучном CPU.
- Электричество и нагрев: 3060 под нагрузкой 170 Вт, карта будет шуметь.


ЧЕГО НЕ ДЕЛАТЬ
--------------------------------------------------------------------------------
- Не запускать npm ci / npm install под работающим стеком: сначала удаляется
  node_modules, и на живом API это ломает дерево (EPERM). Останавливайте API.
- Не выполнять git reset --hard, git checkout -- <файл>, docker system prune:
  в проекте это стирает незакоммиченную работу и образы отката.
- Не держать в Cline авто-одобрение на запись файлов и команды, пока не
  убедитесь, что модель не «фантазирует» правки. Начните с read-only.
- Не включать одновременно облачную и локальную модель в одном запросе —
  контекст и деньги уходят впустую.

КАК ПЕРЕНЕСТИ КОМПЛЕКТ НА ДОМАШНИЙ ПК С 3060
--------------------------------------------------------------------------------
1. Скопируйте папку "D:\ИИ агент\3060 16 gb" целиком (флешка, сеть, облако —
   без разницы, файлы текстовые и маленькие).
2. На домашнем ПК проверьте пути: если проект лежит не в
   D:\swiftmatch1bdnoutprodpart1, поправьте "path" в swiftmatch-3060.code-workspace
   и путь в docs.url файла 06-Continue-автодополнение.yaml.
3. Перенесите .clinerules в корень проекта (рядом с AGENTS.md).
   В комплекте он — копия проектного (синхронизирован 30.10.2026, 8569 байт):
   придумывать заново не нужно, и правки тоже делаются в проекте, а сюда
   переносится копия.
4. Модели НЕ переносятся вместе с папкой: их либо скачивает
   02-Установить-локально.bat на месте, либо копируется папка
   %USERPROFILE%\.ollama\models (только если переносите на такой же Ollama).
5. Порядок на новой машине тот же: драйвер -> Ollama -> скрипт -> расширения ->
   workspace -> проверка "100% GPU".
6. Когда всё поднято — откройте терминал в проекте и выполните
   npm.cmd run task:next -- --local  (см. 07-Автовыбор-задач.txt).

7. Если что-то не запускается и в логе кракозябры или «путь не найден» —
   причина может быть в кириллице внутри "D:\ИИ агент\3060 16 gb".
   Перенесите папку в латиницу: D:\ai-agent\3060-16gb\ и поправьте
   "path" в workspace и docs.url в конфиге Continue (подробно — 10, п.5.2).
